Step 7: Actions that depend on each other

One request, two actions. Action 1 inserts 200 records into the database in 4 batches, each on its own thread. Action 2 processes the records, and must not start before every batch is in. The server chains the two with CompletableFuture and reports the progress of both over one stream.

What to notice

  • The 4 batches move at different speeds: each runs on its own virtual thread. Processing starts only when the slowest one is done, because it's chained with allOf(batches).thenRunAsync(process).
  • Tick "Don't wait": processing starts at the same moment as the inserts, finds the table still empty, and is done at once with 0 records. The summary, read from the database, shows all 200 it missed. With other timings it would miss only some, which is worse: the bug would come and go.
  • Tick "Make batch 3 fail": allOf completes with the error, so thenRunAsync never runs processing. The other batches still finish, and their rows stay in the table.
  • The POST returns right away. Its thread only wires the actions together; the work runs on other threads, and all of them send on the same emitter.

Try it with curl

T=$(curl -s -u alice:password -c jar http://localhost:8080/step7 | grep -o 'name="_csrf" content="[^"]*"' | head -1 | cut -d'"' -f4)
curl -s -u alice:password -b jar -H "X-CSRF-TOKEN: $T" -d dontWait=true http://localhost:8080/step7/jobs   # copy the job id from data-events
curl -N -u alice:password http://localhost:8080/step7/jobs/<job id>/events
