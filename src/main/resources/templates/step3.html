Step 3: Progress of a long task

The form POSTs to /step3/jobs. The server starts the job in the background and answers right away with an HTML fragment. That fragment contains sse-connect, so as soon as htmx inserts it, the browser opens the job's stream and receives progress events until a final done event.

Tip: a task name containing fail makes the job fail at step 6.

What to notice

  • Two requests: POST /step3/jobs (starts the job, returns HTML) and GET /step3/jobs/{id}/events (the stream). Look at the browser's Network tab.
  • Event data is HTML rendered on the server from Thymeleaf fragments. htmx just swaps it in.
  • The job starts before the browser connects. Early events are not lost: the emitter buffers them until the GET returns it.
  • Success and failure both end with a done event, and the stream has sse-close="done". Remember step 1: without it the browser would reconnect to a finished job.
  • Start a second job while one is running: the old fragment is replaced, htmx closes its stream, and the server notices at the next send.

Try it with curl

curl -s -d task=demo http://localhost:8080/step3/jobs   # copy the job id from sse-connect
curl -N http://localhost:8080/step3/jobs/<job id>/events
