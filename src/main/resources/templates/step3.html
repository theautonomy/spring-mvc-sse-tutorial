Step 3: Progress of a long task

The form POSTs to /step3/jobs. The server starts the job in the background and answers right away with an HTML fragment. The page inserts it, reads the stream URL from its data-events attribute, and opens an EventSource that receives progress events until a final done event.

Tip: a task name containing fail makes the job fail at step 6.

What to notice

  • Two requests: POST /step3/jobs (starts the job, returns HTML) and GET /step3/jobs/{id}/events (the stream). Look at the browser's Network tab.
  • Event data is HTML rendered on the server from Thymeleaf fragments. The page just sets innerHTML. That is safe here because the server escapes everything with th:text.
  • The job starts before the browser connects. Early events are not lost: the emitter buffers them until the GET returns it.
  • Success and failure both end with a done event, and the page calls es.close() when it arrives. Remember step 1: without it the browser would reconnect to a finished job.
  • Start a second job while one is running: the page closes the old stream itself (removing its HTML does not), and the server notices at the next send.

Try it with curl

curl -s -d task=demo http://localhost:8080/step3/jobs   # copy the job id from data-events
curl -N http://localhost:8080/step3/jobs/<job id>/events
