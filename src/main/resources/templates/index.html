Server-Sent Events with Spring MVC and plain JavaScript

Server-Sent Events (SSE) let the server push data to the browser over one long HTTP response. Each step below is a small working example that builds on the one before it. The browser side uses only EventSource and fetch: no framework. TUTORIAL.md in the repo explains every step in detail.

You are logged in as alice. Steps marked admin need the ADMIN role (log in as admin); for everyone else, their page and stream answer 403.

  1. Step 1: Hello world

    The SSE wire format, SseEmitter, plain EventSource, and why the browser keeps reconnecting.

  2. Step 2: A ticking clock

    A long-lived stream, named events and addEventListener, emitter timeouts and cleanup.

  3. Step 3: Progress of a long task

    POST starts a job, the response opens its stream, HTML fragments as events, closing the stream on done, errors.

  4. Step 4: A live dashboard admin

    One stream, many named events, each updating its own part of the page.

  5. Step 5: A chat room

    Broadcast to many tabs, dead-client cleanup, heartbeats, event ids and catching up after a reconnect.

  6. Step 6: Ask the user admin

    Two-way flow: the job pauses, asks a question over SSE, and continues when the answer is posted.

  7. Step 7: Actions that depend on each other

    Insert records into a database on several threads, then process them only once every insert is done. CompletableFuture sets the order, SSE shows the progress.

  8. Step 8: The pipeline, for real

    Job state in the database, a stream that survives reloads, transactional batches with retry, a limit on parallel work, cancel, timeout, cleanup.
