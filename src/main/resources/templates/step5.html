Step 5: A chat room

Open this page in two browsers (or a normal and a private window), one logged in as alice and one as bob. Each tab has its own stream; the server keeps all of them in a list and broadcasts every message to each one. Sending a message is a normal POST.

    What to notice
    
        
      
            
    • The presence count changes as tabs open and close. The server removes a tab when its stream
                completes or when a send to it fails.
      • 
            
    • Every 15 s the server sends a comment line (: ping). The browser ignores it, but the write
                tells the server whether the tab is still there.
      • 
            
    • Every message event has an id. Press "Simulate a dropped connection", post from another tab,
                and watch this tab reconnect after 5 s (the retry the server sent) and receive only the
                missed messages. The browser sends the last id in the Last-Event-ID header. The page has no
                reconnect code at all: EventSource does it.
      • 
            
    • Messages are rendered with th:text, so HTML typed into the chat is escaped before the page
                inserts it with insertAdjacentHTML. Broadcasting unescaped user input would be an XSS hole
                for every connected tab.
      • 
        
    
    
    

    
    
        
    Try it with curl
    
        
    curl -N -u bob:password "http://localhost:8080/step5/stream?tab=curl"
curl -N -u bob:password -H "Last-Event-ID: 3" "http://localhost:8080/step5/stream?tab=curl"   # replay after message 3
# Posting needs the CSRF token (see step 3). The author is always the logged-in user.
T=$(curl -s -u bob:password -c jar http://localhost:8080/step5 | grep -o 'name="_csrf" content="[^"]*"' | head -1 | cut -d'"' -f4)
curl -u bob:password -b jar -H "X-CSRF-TOKEN: $T" -d text=hello http://localhost:8080/step5/messages
